# 在 Lingma 中使用 Impeccable 设计指南

虽然 Lingma 不直接支持 impeccable 的技能系统，但你可以通过以下方式使用这些设计原则。

## 方法 1: 引用文档（推荐）

在需要设计改进时，告诉 Lingma 参考相关文档：

```
请根据 docs/impeccable/color-and-contrast.md 的指导，优化应用的颜色方案
```

```
参考 docs/impeccable/typography.md，改进应用的字体层次结构
```

```
按照 docs/impeccable/spatial-design.md 的间距系统，重构 TodayScreen 的布局
```

## 方法 2: 使用关键原则

直接从本文档中引用关键反模式：

### 颜色使用

```
避免在内部小卡片中使用蓝色 - 与深蓝色应用背景对比度差
推荐使用：橙色 (#FFB74D)、绿色 (#64DD17)、红色、琥珀色
```

### 卡片设计

```
不要把所有内容都包裹在卡片中
不要在卡片内嵌套卡片
使用留白和分隔线创造视觉层次
```

### 圆角规范

```
Material Design 3 卡片圆角标准：
- 主卡片：8px
- 内部小卡片：4px
- 对话框：12-16px
- 按钮：完全圆角
```

## 方法 3: 代码审查清单

在审查 UI 代码时，使用这个清单：

### 视觉检查

- [ ] 是否使用了系统默认字体？应该选择品牌字体
- [ ] 是否有灰色文本在彩色背景上？这是反模式
- [ ] 是否过度使用卡片？考虑用留白替代
- [ ] 颜色是否符合 60-30-10 规则？
- [ ] 对比度是否满足 WCAG AA 标准（4.5:1）？

### 交互检查

- [ ] 按钮是否有明确的悬停和点击状态？
- [ ] 加载状态是否有骨架屏？
- [ ] 错误消息是否清晰友好？
- [ ] 是否有适当的焦点指示器？

### 响应式检查

- [ ] 在小屏幕上是否正常显示？
- [ ] 触摸目标是否至少 48x48px？
- [ ] 文本是否在长文本时会溢出？

## 常用场景示例

### 场景 1: 创建新页面

```
我要创建一个新的设置页面。请根据 impeccable 的设计原则：
1. 参考 docs/impeccable/layout.md 设计布局
2. 遵循 docs/impeccable/interaction-design.md 实现交互
3. 使用项目现有的 AppColors 和 AppSpacing 常量
4. 避免常见的 AI 设计反模式
```

### 场景 2: 优化现有页面

```
TodayScreen 看起来太平淡了。请根据 docs/impeccable/bolder.md 的指导：
1. 强化视觉层次
2. 增加一些微妙的动效
3. 优化颜色使用，让重要元素更突出
4. 但不要过度设计，保持简洁
```

### 场景 3: 添加动画

```
为城市列表添加交错过渡动画。参考 docs/impeccable/motion-design.md：
1. 使用自然的缓动曲线（不要用弹跳效果）
2.  stagger 延迟约 50-100ms
3. 尊重用户的减少运动偏好设置
4. 动画时长控制在 200-300ms
```

## 快速参考卡片

### OKLCH 色彩空间

```dart
// 好的做法：使用带色调的中性色
Color neutral = Color(0xFFF8FAFC); // 带微量蓝色的灰
Color primary = Color(0xFF6366F1); // Indigo 品牌色

// 避免：纯灰色
Color bad = Color(0xFF808080); // ❌ 死气沉沉
```

### 间距系统

```dart
// 推荐的间距值
const double xs = 4;   // 图标内边距
const double sm = 8;   // 紧凑间距
const double md = 12;  // 标准间距
const double lg = 16;  // 卡片间距
const double xl = 24;  // 区块间距
const double xxl = 32; // 大区块间距
```

### 60-30-10 规则

```
60% - 中性背景、留白、基础表面
30% - 次要颜色：文本、边框、非激活状态
10% - 强调色：CTA 按钮、高亮、焦点状态
```

## 有用的命令

虽然这些命令主要在 Claude Code 中使用，但你可以参考它们的思路：

| 命令                   | 用途         | Lingma 中的替代方式                |
| ---------------------- | ------------ | ---------------------------------- |
| `/impeccable audit`    | 技术质量检查 | "检查这个页面的可访问性和性能问题" |
| `/impeccable critique` | UX 审查      | "从用户体验角度审查这个设计"       |
| `/impeccable polish`   | 最终优化     | "帮我做最后的细节优化"             |
| `/impeccable bolder`   | 强化设计     | "让这个设计更有视觉冲击力"         |
| `/impeccable distill`  | 简化设计     | "简化这个复杂的界面"               |

## 提示词模板

复制这些模板用于日常开发：

### 模板 1: 新组件设计

```
请设计一个 [组件名称]，遵循以下原则：
- 参考 docs/impeccable/[相关文档].md
- 使用项目的 AppColors、AppSpacing、AppRadius 常量
- 避免 impeccable 反模式（不使用默认字体、不过度使用卡片等）
- 确保良好的可访问性（对比度、触摸目标大小）
- 提供 light 和 dark 两种主题的实现
```

### 模板 2: 设计改进

```
当前的 [页面/组件] 存在以下问题：
- [问题 1]
- [问题 2]

请根据 impeccable 设计指南进行改进：
- 参考 docs/impeccable/README.md 中的相关章节
- 重点关注 [颜色/排版/间距/动效]
- 保持与现有设计风格的一致性
- 提供具体的代码修改建议
```

### 模板 3: 代码审查

```
请审查这段 UI 代码，检查是否存在以下 impeccable 反模式：
1. 使用了系统默认字体
2. 灰色文本在彩色背景上
3. 过度使用卡片或卡片嵌套
4. 使用了弹跳/弹性缓动
5. 纯黑色或纯灰色

文件：[文件路径]
重点关注：[具体方面]
```
